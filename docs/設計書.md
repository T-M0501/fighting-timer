# Fighting Timer 設計書

## 1. 構成（ビルド不要・HTML/CSS/JavaScriptのみ）

| ファイル | 役割 |
|---|---|
| `index.html` / `styles.css` | 画面の骨組みと見た目（ライトモード固定） |
| `js/model.js` | データ構造、範囲チェック(30分/99セット/99周)、バックアップ検証、時間表示 |
| `js/engine.js` | **進行計画 `buildPlan()`** と **タイマー `TimerEngine`**（画面・音に依存しない） |
| `js/db.js` | IndexedDB保存（版番号つき）。使えない環境ではメモリ保存に自動切替 |
| `js/audio.js` | 電子音(Web Audio)と日本語音声(SpeechSynthesis) |
| `js/core.js` | 状態と保存操作、Service Worker登録、安全な自動更新 |
| `js/screens-*.js`, `js/app.js` | 画面とルーター |
| `sw.js`, `manifest.webmanifest`, `icons/` | PWA（オフライン・ホーム画面追加） |
| `tools/` | 補助スクリプト（ローカルサーバー、アイコン生成、版番号の更新） |
| `tests/` | 自動テスト（`npm test`） |

## 2. 重要な設計判断

- **計画の一元化**: 合計予定時間も実際のタイマー進行も、必ず `buildPlan(menu)` が返す同じ区間リスト(準備/運動/休憩)を使う。休憩の挿入は `restBetween()` 1か所だけで決めるため、休憩の重複は起きない。
  - 休憩の決定: 周回が変わる→周回間休憩 / 種目が変わる→種目間休憩 / 同じ種目の次のセット→セット間休憩。0秒の準備・休憩は区間を作らない。
  - サーキットでは各種目を1周につき1回行う（種目ごとのセット数は使わず、周回数で繰り返す）。サーキットにはセット間休憩はない。
- **時刻差分方式**: `TimerEngine.tick(now)` は開始時刻との差で位置を計算する。`setInterval` の回数は使わないので、遅延や画面非表示からの復帰でも正しい残り時間になる。
- **再開前3秒**: 一時停止→「再開」で3秒カウント（status=`resuming`）。この3秒は運動・休憩時間に含めず、一時停止時の残り時間から再開する。
- **リセット**: 確認ダイアログで「リセットする」を選んだ場合のみ最初に戻る。キャンセル時は何も変えない。リセットした記録は履歴に保存されない。
- **履歴**: 実施日時（トレーニング開始時刻）・メニュー名・実施時間(計画の合計)のみ。終了時に「履歴を保存/保存せず終了」を選ぶ。メニューを削除しても履歴は残る。
- **保存**: IndexedDB（`menus`/`exercises`/`history`/`meta`）。DB版は `db.js` の `DB_VERSION`。将来は `onupgradeneeded` に段階的な移行を追記する。読み込み時は全データを `sanitize*` で補正するため、項目が増えても古いデータで壊れない。
- **復元**: ファイルを検証（形式名・版・内容・範囲）→確認→1つのトランザクションで置換。途中で失敗すると元データは変わらない。
- **自動更新**: Service Workerは新版を取得後「待機」状態にし、アプリが **トレーニング画面(#/run)以外かつメニュー編集中でない** ときだけ `SKIP_WAITING` を送って再読み込みする。
- **音の設計**: `audio.js` の冒頭コメント参照（矩形波・十分な振幅・コンプレッサー＋ソフトクリッパーで音割れ防止・エンベロープでクリック音防止・音声は音量1.0固定）。

### 休憩ルール（種目ごとの個別設定を追加）
「種目ごとに全セット」方式では、各種目に **サイクル数**（セットをまとめて繰り返す回数）と、3つの休憩の個別設定（空=メニュー共通の値）を持てる。
- 同じサイクル内のセットの間 → 種目の「セット間休憩」(空ならメニューの セット間休憩)
- サイクルの間 → 種目の「サイクル間休憩」(空ならメニューの サイクル間休憩)
- 種目が終わったあと → 種目の「終了後の休憩」(空ならメニューの 種目間休憩)。最後のセットの後だけ長く休みたい場合に使う。
- サーキット方式ではこの個別設定は使わない。休憩が0秒なら区間を作らない。
- 例: 背筋 4セット×2サイクル →(終了後60秒)→ スクワット … は `tests/engine.test.js` で検証。

## 3. 仕様上の解釈（確定仕様と矛盾しない範囲で決めたもの）

1. 履歴の実施日時は「開始時刻」。
2. 音声ガイド: 準備開始「次は○○」/ 運動開始「運動開始」(最初の種目で準備0秒のときは「○○、運動開始」)/ 休憩開始「休憩開始。次は○○」/ 終了「トレーニング終了です」。セット数・周回数は読まない。
3. カウントダウン電子音は準備・運動・休憩のどの区間でも、終了のN秒前から1秒ごとに鳴る。
4. 通知は「試験的」。画面が見えない間に端末がJavaScriptを動かし続けた場合のみ通知を試みる（iPhoneでは保証されない）。
5. 一時停止中・再開待機中は「リセット」が使える。サーキット/種目完了型の切替で使われない項目の設定値は保持される。

## 4. 既知の制限
- iPhoneは本体の最大音量を超えて鳴らせない。サイレントスイッチ・Bluetooth接続状況の影響を受ける。
- 画面ロック中・別アプリ表示中はiOSがJavaScriptを止めるため、その間は音も鳴らない。復帰時に実際の経過時間で表示を修正する（その間の音は鳴らない）。
- 画面点灯維持は、当初仕様では非搭載だったが、ご要望により設定「トレーニング中は画面をスリープさせない」(初期値オン)として追加。タイマー実行中・一時停止中のみ働く(Wake Lock API)。非対応の端末・省電力モード時は働かない。
- メニュー一覧に「通常表示/詳細表示」の切替を追加(選択は設定に保存)。トップ画面にボクシンググローブのイラストを追加。
- iOSはPWAをホーム画面に追加しない場合、一定期間使わないとサイトデータを消去することがある。ホーム画面に追加し、定期的にバックアップを保存すること。
